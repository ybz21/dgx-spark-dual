## 两台机器

| | `.8` | `.12` |
|---|---|---|
| hostname | `spark-e9d7` | `spark-c915` |
| 架构 / GPU | aarch64 / NVIDIA GB10 | aarch64 / NVIDIA GB10 |
| 内存 | 119 GiB 统一内存 | 119 GiB 统一内存 |

| RoCE HCA | `rocep1s0f1`（对应 f1 口） | `rocep1s0f1` |

四个 RoCE 设备的口对应关系两台一致：

```
rocep1s0f0   -> enp1s0f0np0
rocep1s0f1   -> enp1s0f1np1     <- 在用的这条
roceP2p1s0f0 -> enP2p1s0f0np0
roceP2p1s0f1 -> enP2p1s0f1np1
```

> ⚠️ 仓库根 README 里写的是 `enp1s0f0np0` + `10.0.0.1/10.0.0.2`，
> 实机是 **f1 口** + `10.0.0.2/10.0.0.3`。Entrpi kit 的 `.env.example` 默认也是 f0，
> 照抄会让 NCCL 建不起来。

## 内存现状（部署的唯一阻塞项）

```
.8   119 GiB 总，已用 112，可用 7
.12  119 GiB 总，已用 110，可用 9
```

Entrpi kit 要求起服务前**系统内存占用 < 6 GB**，现在差得远。

但 `docker stats` 显示所有容器 RSS 加起来只有：

| | 容器 RSS 合计 | 最大的单个 |
|---|---|---|
| `.8` | ~2.5 GiB / 20 个容器 | `devbox-nexus` 1.23 GiB、`ds4-dspark-2x-vllm-dspark-1` 872 MiB |
| `.12` | ~1.2 GiB / 8 个容器 | `ds4-dspark-2x-vllm-dspark-1` 856 MiB |

**差出来的 108 GiB 是 DeepSeek-V4-Flash 那套 vLLM 占的统一内存**，
GPU 侧的分配不进容器 RSS 统计，只在 `free` 里体现。结论：

- 停 `ds4-dspark-2x-vllm-dspark-1`（两台都要）就能把内存腾出来
- `.8` 上那一堆 blade-* / gitea / grafana / prometheus / nexus 业务容器
  总共不到 700 MiB，不用动
- DS4 双节点那套**还有评测没跑完**（见仓库 `models/deepseek-v4-flash/`），
  停之前先跟人确认；用 `docker stop` 不要 `rm`，回头 `docker start` 就能回来
